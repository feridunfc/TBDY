# MIGRATION_PLAN.md

## Objective

Move TBDY_ENGINE v3.0 to one production execution path:

```text
runner_v2
-> runtime scheduler
-> runtime evaluation DAG
-> adapter
-> reports
```

without modifying immutable engineering modules.

## Current Migration Status

Partial.

Implemented pieces:

- contracts directory exists
- runtime scheduler exists
- runtime DAG exists
- module cache exists
- check adapter exists
- JSON and Excel reporters exist
- runner_v2 exists
- contract validation currently has 0 hard errors
- root tests pass

Blocking gaps:

- legacy `runner.py` remains exported through package API
- legacy runner tests remain active
- final report generation has a separate tools pipeline
- report layout is hardcoded in reporters/tools, not fully driven by `reports.yaml`
- `include_legacy=True` is default in `runner_v2` and contract loader
- 45 legacy mapping warnings remain
- no coverage evidence
- no golden suite evidence tied exclusively to v3 runtime

## Phased Migration

### Phase 0 — Freeze Scope

Allowed only:

- stabilization
- correctness
- validation
- reporting contract alignment
- v3 runtime consolidation

Forbidden:

- optimization
- ML
- AI recommendations
- UI/dashboard/cloud
- foundation redesign
- diaphragm redesign

Gate: no new feature branches merged into v3 tunnel.

### Phase 1 — Production Entry Point Lock

Goal: eliminate accidental legacy production entry.

Smallest safe delta:

1. Stop exporting legacy `run` as the primary package API.
2. Export `run_engine_v2` explicitly.
3. Keep legacy `runner.py` file physically present but mark it non-production.
4. Move legacy tests to an explicit legacy test marker or quarantine folder.

Gate:

- importing `tbdy_engine` must not silently select legacy runtime
- production docs must point only to `runner_v2`

Impact score: 4

### Phase 2 — Contract Loader Strict Mode

Goal: make production contract loading deterministic.

Smallest safe delta:

1. Change production/default runtime to `include_legacy=False`.
2. Keep `include_legacy=True` only for audit/migration tools.
3. Fail production validation on legacy enrichment warnings.
4. Preserve generated runtime catalog snapshots for audit only.

Gate:

- production catalog derives only from `contracts/*.yaml`
- no legacy YAML can alter runtime catalog silently

Impact score: 5

### Phase 3 — Report Contract Binding

Goal: make `reports.yaml` the source of truth for report sections, formats, included fields, filters, and metrics.

Smallest safe delta:

1. Pass report contract from `runner_v2` into reporters.
2. Replace hardcoded reporter field lists with `reports.yaml` lookups.
3. Keep JSON/Excel writers as format emitters only.
4. Move final post-processing tools behind the same report contract or remove them from production path.

Gate:

- no hardcoded report structure in production reporters
- final report generated by one reporting path

Impact score: 5

### Phase 4 — Runtime / DAG Validation Gate

Goal: promote current DAG checks into mandatory release gate.

Smallest safe delta:

1. Add explicit DAG validation command.
2. Fail on missing enabled dependencies.
3. Fail on circular dependencies.
4. Emit deterministic execution order artifact.
5. Verify cache keys are unique among enabled evaluations.

Gate:

- DAG valid
- no circular dependency
- deterministic execution
- cache correctness

Impact score: 4

### Phase 5 — Golden Suite and Coverage Gate

Goal: production release proof.

Smallest safe delta:

1. Add golden tests that execute only `runner_v2` production path.
2. Add coverage measurement.
3. Fail release if coverage is below 95%.
4. Ensure golden report outputs are reproducible except timestamps/snapshots.

Gate:

- golden tests pass
- coverage >=95%

Impact score: 4

## Current Decision

REJECT production release.

Reason: single runtime, single reporting path, contract-only reporting, coverage, and golden-suite gates are not yet satisfied.
