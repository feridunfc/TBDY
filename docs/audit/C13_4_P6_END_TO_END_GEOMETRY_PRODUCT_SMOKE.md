# C13.4-P6 End-to-End Geometry Product Smoke Command

## 1. Sprint purpose

C13.4-P6 adds one deterministic end-to-end geometry product smoke command. It orchestrates the already-accepted C13.4 geometry pipeline:

```text
FeatureSnapshot-like JSON
→ C13.4-P4 JSON artifacts
→ C13.4-P5 Markdown report
→ product smoke summary and manifest
```

This sprint is orchestration-only. It does not add engineering checks and does not change P3, P4, or P5 semantics.

## 2. Product smoke boundary

The product smoke module is:

```text
tbdy_engine/product/geometry_product_smoke.py
```

The CLI is:

```text
tools/run_geometry_product_smoke.py
```

The P6 module calls P4 and P5 APIs only. It does not call `MinimalCheckEngine` directly and does not call the P3 adapter directly.

## 3. Input contract

The command accepts one local FeatureSnapshot-like JSON file path:

```bash
--feature-snapshot tests/fixtures/c13_4_p4/geometry_feature_snapshots.json
```

Optional catalog directory:

```bash
--catalog-dir tbdy_engine/catalogs
```

No ETABS, Excel, Streamlit, live provider, or network data source is accepted.

## 4. Output directory contract

The output directory structure is fixed:

```text
<output_dir>/
  artifacts/
    check_results.json
    adapter_diagnostics.json
    run_summary.json
    run_manifest.json
  reports/
    geometry_report.md
  product_smoke_summary.json
  product_smoke_manifest.json
```

The P4 artifacts are generated by the P4 runner. The Markdown report is generated by the P5 renderer.

## 5. P4 reuse statement

P6 calls:

```python
run_geometry_vertical_slice_from_file(
    feature_snapshot_path=feature_snapshot_path,
    output_dir=output_dir / "artifacts",
    catalog_dir=catalog_dir,
)
```

P6 does not manually recreate P4 artifacts, call `MinimalCheckEngine`, or call the P3 adapter.

## 6. P5 reuse statement

P6 calls:

```python
render_geometry_markdown_report_from_artifact_dir(
    artifact_dir=output_dir / "artifacts",
    output_path=output_dir / "reports" / "geometry_report.md",
)
```

P6 does not manually recreate the Markdown report and does not duplicate P5 table rendering logic.

## 7. Summary JSON contract

P6 writes:

```text
<output_dir>/product_smoke_summary.json
```

Required content groups:

- `status`
- `scope`
- `feature_snapshot_path`
- `artifact_dir`
- `report_path`
- `p4`
- `p5`
- `outputs`

`status: OK` means the geometry product smoke completed. It is not a final building compliance verdict.

P4 values come from P4 `run_summary`/result data. P5 values come from the P5 render result.

## 8. Manifest JSON contract

P6 writes:

```text
<output_dir>/product_smoke_manifest.json
```

Required content groups:

- `runner`
- `scope`
- `feature_snapshot_path`
- `output_dir`
- `artifact_dir`
- `report_dir`
- `report_path`
- `source_steps`
- `artifact_files`
- `guardrails`
- `forbidden_scope`

The manifest lists the fixed output bundle and the orchestration guardrails.

## 9. Determinism policy

P6 output is deterministic:

- fixed output directory structure;
- fixed artifact file list;
- no timestamps;
- no random IDs;
- no environment-dependent extra metadata;
- JSON files use `indent=2`, `sort_keys=True`, `ensure_ascii=False`, and final newline;
- Markdown is generated by the deterministic P5 renderer;
- repeated runs with the same input and output directory should produce identical file contents.

## 10. Guardrails

The manifest includes:

| guardrail | value |
| --- | --- |
| geometry_only | true |
| orchestration_only | true |
| new_engineering_checks_added | false |
| etabs_live_fetching_used | false |
| excel_production_path_used | false |
| streamlit_ui_used | false |
| legacy_runtime_used | false |
| rebar_flexure_shear_capacity_unlocked | false |
| modal_mass_unlocked | false |
| final_building_compliance_verdict_emitted | false |

## 11. Explicitly excluded engineering scope

P6 excludes:

- beam flexure;
- beam shear;
- rebar adequacy;
- capacity design;
- governing combo selection;
- force envelope selection;
- SCWB;
- column PMM;
- drift compliance;
- modal mass checks;
- column area checks;
- column aspect ratio checks;
- final building compliance verdict;
- ETABS live fetching;
- Excel production path;
- Streamlit UI;
- live provider execution;
- legacy runtime/design execution.

## 12. Legacy boundary statement

The P6 module and CLI must not import:

- `tbdy_engine.design`
- `tbdy_engine.adapters.check_adapter`
- `tbdy_engine.engine.topology`
- `tbdy_engine.runtime`
- `tbdy_engine.runner_v2`
- `tbdy_engine.archx`

The P6 module must not import:

- `MinimalCheckEngine`
- `build_geometry_check_inputs_from_feature_snapshot`

The boundary audit now scans:

```text
tbdy_engine/product/*.py
```

P6 tests also inspect product module and CLI source text for forbidden imports and direct engine/adapter calls.
